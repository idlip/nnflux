#+TITLE: nnflux: Gnus backend for Miniflux (read RSS/Atom feeds in Emacs)
#+DESCRIPTION: nnflux is a Gnus backend and Emacs Miniflux client. Read your self-hosted Miniflux RSS and Atom feeds as normal Gnus groups, with read and star state synced both ways.
#+KEYWORDS: gnus, miniflux, emacs, rss, atom, feed reader, newsreader, nnflux, emacs-lisp

*nnflux* is a [[https://www.gnu.org/software/emacs/manual/html_node/gnus/][Gnus]] backend for [[https://miniflux.app/][Miniflux]]. It lets you read feeds from a self-hosted Miniflux server inside Emacs, as normal Gnus groups, using Miniflux's native REST API. If you want to read RSS in Gnus, or want a Miniflux client for Emacs that is not built on Elfeed, this is it.

#+begin_quote
  This package was written with the help of AI for accomplishing its purpose.
#+end_quote

* Features

- One Gnus group per Miniflux feed.
- Read/unread marks sync both ways with the server.
- Star (Gnus =!= "tick" mark) syncs both ways with Miniflux bookmarks.
- Server is treated as the source of truth on pull (~M-g~ or re-entering a group): local marks for any
  article the server reports on are set to match it, so there is no manual conflict resolution.
- Token auth (~X-Auth-Token~) or HTTP Basic Auth (account username/password).
- No local article database, articles are fetched live into memory each time you open a group.

* Install

** With =use-package= and =:vc= (Emacs 30+)

#+begin_src emacs-lisp
(use-package nnflux
  :vc (:url "https://github.com/idlip/nnflux" :rev :newest)
  :after gnus)
#+end_src

** Manual

Download =nnflux.el= and load it directly:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/nnflux")
(require 'nnflux)
#+end_src

* Setup

With an API token (Miniflux: Settings -> API Keys -> Create a new API key):

#+begin_src emacs-lisp
  (setq nnflux-address "https://miniflux.domain.tld")
  (setq gnus-select-method
        '(nnnil ""))
  (setq gnus-secondary-select-methods
        '((nnflux "home"
           (nnflux-address "https://miniflux.domain.tld")
           (nnflux-token "your-api-token"))

          ;; to flatten all miniflux feeds into one group.
          ;; refer: info:gnus#Combined Groups
          (nnvirtual "all-feeds"
                     (nnvirtual-component-regexp "^nnflux\\+home:"))))
#+end_src

Or with your account username/password instead of a token:

#+begin_src emacs-lisp
(setq gnus-secondary-select-methods
      '((nnflux "home"
         (nnflux-address "https://miniflux.domain.tld")
         (nnflux-user "your-username")
         (nnflux-password "your-password"))))
#+end_src

Or leave both unset and store the credential in =auth-source= (=~/.authinfo=, =~/.authinfo.gpg=, etc.)
instead, keyed on =nnflux-address='s host. For an API token, use a login of =api-token= (also accepts
=token= or =nnflux-token=) so it's recognized as a token rather than a password:

#+begin_src conf
machine miniflux.domain.tld login api-token password your-api-token
#+end_src

Any other login is treated as a Basic Auth username/password pair.

* Usage

All through normal Gnus keys, once subscribed to a group:

- Mark read/unread: normal Gnus commands.Pushed to the server when you leave the group (~q~).
- Star: Gnus's tick mark (~!~ to tick, ~M-u~ to untick).
- Pull server changes (e.g.read on the Miniflux phone app): ~M-g~ on the group, or re-enter it.
- Describe a feed (title, description, site url): ~d~ (~gnus-group-describe-group~) in the Group buffer.
- Subscribe to a new feed: ~M-x nnflux-subscribe-feed~, then enter a feed URL. Gnus's normal new-group prompt picks it up from there (equivalent to pressing ~g~).
- Search: ~G G~ runs Miniflux's own full-text search across your feeds (or the marked/current group, if narrowed). Only matches within each feed's normal fetch window (~nnflux-fetch-limit~) are reachable; anything older is reported as skipped rather than silently dropped. Requires Emacs new enough to have ~gnus-search.el~.

* Extending nnflux

nnflux ships a small, fixed set of commands (subscribe, search, describe, mark sync) for integrating with gnus specifically.

For anything else [[https://miniflux.app/docs/api.html][Miniflux's API]] supports, check for nnflux helper functions (=C-h f nnflux-= ): ~nnflux--pick-server~, ~nnflux--use-server~, and ~nnflux--get~ - ~nnflux--put~ - ~nnflux--post~ act as base callers.

** Refresh a feed right now

Example: refresh a feed right now, picked from a ~completing-read~ list annotated with
each feed's category/site/last-checked/error:

#+begin_src emacs-lisp
  (defun nnflux-refresh-feed ()
    "Ask Miniflux to re-poll one feed URL right now."
    (interactive)
    (let* ((server (nnflux--pick-server))
           (_ (nnflux--use-server server))
           (feeds (nnflux--get "/feeds"))
           (table (make-hash-table :test 'equal))
           (candidates
            (mapcar (lambda (feed)
                      (puthash (alist-get 'title feed) feed table)
                      (alist-get 'title feed))
                    feeds))
           (width (apply #'max (mapcar #'length candidates)))
           (completion-extra-properties
            (list :annotation-function
                  (lambda (c)
                    (let ((f (gethash c table)))
                      (format "%s%s, checked %s"
                              (make-string (- (+ width 3) (length c)) ?\s)
                              (alist-get 'site_url f) (alist-get 'checked_at f))))))
           (choice (completing-read "Refresh feed: " candidates nil t))
           (feed-id (alist-get 'id (gethash choice table))))
      (nnflux--put (format "/feeds/%d/refresh" feed-id) nil)
      (message "nnflux: refreshed feed %d" feed-id)))
#+end_src

=PUT /feeds/{id}/refresh= is synchronous, press ~M-g~ on the group to pull them into Gnus.
Ideally miniflux should be configured to poll globally as desired.

* Testing

Unit tests (~nnflux-tests.el~, using Emacs's built-in =ert=) cover the pure functions -- no network
needed:

#+begin_src bash
  emacs -Q -batch -l ert -l nnflux.el -l nnflux-tests.el -f ert-run-tests-batch-and-exit
#+end_src

There are also live tests that exercise the backend against a real Miniflux server (list feeds, open
a group, fetch headers/an article). They are strictly read-only -- they never push marks -- and skip
automatically if no server is configured. Point them at a server with environment variables:

#+begin_src bash
  NNFLUX_TEST_URL=http://localhost:8080 \
  NNFLUX_TEST_TOKEN=your-api-token \
  emacs -Q -batch -l ert -l nnflux.el -l nnflux-tests.el ert-run-tests-batch-and-exit

  # or with Basic Auth instead of a token:
  NNFLUX_TEST_URL=https://miniflux.domain.tld \
  NNFLUX_TEST_USER=you NNFLUX_TEST_PASSWORD=secret \
  emacs -Q -batch -l ert -l nnflux.el -l nnflux-tests.el -f ert-run-tests-batch-and-exit
#+end_src

** Running a local Miniflux, no Docker, no root

Miniflux needs PostgreSQL: the =miniflux= binary runs as any user, and Postgres can be invoked via =initdb= and =pg_ctl= as a plain user is the standard way to run it anyway.

=shell.nix= and =.envrc= in this repo set up both binaries and all the paths/env vars below,
entirely inside this repo directory (nothing touches your real data or a system-wide install).
With [[https://direnv.net/][direnv]] installed, =direnv allow= once picks up =shell.nix= and exports everything from
=.envrc=; without direnv, run =nix-shell= and =source .envrc= yourself.

First-time setup (creates the database and an admin account):

#+begin_src bash
  direnv allow   # or: nix-shell, then: source .envrc

  initdb -D "$NNFLUX_PGDATA" -U miniflux --auth=trust
  pg_ctl -D "$NNFLUX_PGDATA" -l "$NNFLUX_TEST_DIR/pg.log" \
         -o "-p $NNFLUX_PGPORT -k $NNFLUX_PGSOCK -h ''" start
  createdb -h "$NNFLUX_PGSOCK" -p "$NNFLUX_PGPORT" -U miniflux miniflux

  RUN_MIGRATIONS=1 CREATE_ADMIN=1 \
  ADMIN_USERNAME="$NNFLUX_TEST_USER" ADMIN_PASSWORD="$NNFLUX_TEST_PASSWORD" \
  miniflux
#+end_src

=DATABASE_URL=/=LISTEN_ADDR= (Miniflux's own config vars) are already set by =.envrc=, so once
migrations and the admin account exist, later runs are just:

#+begin_src bash
nnflux-pg-start   # starts postgres, then miniflux in the background
# ... work ...
nnflux-pg-stop    # stops both
#+end_src

Those two are helper scripts from =shell.nix= itself (via =pkgs.writeShellScriptBin=) and put on =PATH= as soon as =direnv allow= (or =nix-shell=) loads it. They need no extra tool or file, and they work the same in bash, zsh, fish, or any other shell. direnv can only export /shell functions/ to bash and zsh (never fish), so these are built as standalone commands instead.

Equivalent by hand: =pg_ctl -D "$NNFLUX_PGDATA" ... start=, then =miniflux &=.

To try it out, subscribe to a test feed and run the test suite against the live server:

#+begin_src bash
  curl -u "$NNFLUX_TEST_USER:$NNFLUX_TEST_PASSWORD" -X POST "$NNFLUX_TEST_URL/v1/feeds" \
       -H 'Content-Type: application/json' \
       -d '{"feed_url":"https://miniflux.app/feed.xml"}'

  emacs -Q -batch -l ert -l nnflux.el -l nnflux-tests.el -f ert-run-tests-batch-and-exit
#+end_src

To stop: =pg_ctl -D "$NNFLUX_PGDATA" stop= (and kill the =miniflux= process). Data persists in =miniflux-test/= (gitignored) between runs, so this also works as a real, always-on local instance to point your actual =gnus-secondary-select-methods= at, not just a throwaway test server, skip =CREATE_ADMIN=1= after the first run once the account exists.
